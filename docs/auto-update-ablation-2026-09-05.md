# 自动更新消融实验（2026-09-05）

## 范围与方法

只研究 Account Switcher 自动更新实现。公开最新版本在本轮核对时为 [v0.1.6](https://github.com/liuzhao1225/codex-account-switcher/releases/tag/v0.1.6)，当前开发候选为 0.1.7 / build 7，尚未发布。

固定 Sparkle 2.9.6、同一份测试更新条目、同一回调顺序及同一组观察项。以修改前的 `AppUpdater.swift` 为基线，分别去掉一项逻辑，再运行组合精简版。所有变体独立编译，调用真实 Sparkle 对象及其 delegate；测试应用使用独立 bundle ID，不接触正式账号和 Codex 历史。

原始文件与结果保存在 `.build/update-ablation/`：`baseline.swift`、`simplified.swift`、`Runner.swift`、`DelegateProbe.m`、`run.py`、`results.json` 以及各变体的编译、运行日志。复现命令：`python3 .build/update-ablation/run.py`。

这是回调及状态行为实验。没有把配置为 3600 秒等同于已等待一小时，也没有把回调测试等同于实际网络下载、签名验证、进程重启或用户可用性实验。实验中的更新条目和回调由测试驱动。

## 结果

| 单项消融 | 观察结果 | 决定 |
| --- | --- | --- |
| 删除上次检查时间及其监听 | 其他全部观察项与基线一致；该状态没有任何产品读取点 | 删除 |
| 删除自动检查开关的重复存储与监听，直接读取 Sparkle 设置 | 开关开/关及 SwiftUI 变更通知均保留，其他观察项与基线一致 | 删除副本，只在用户设置时通知 UI |
| 允许切号期间后台检查版本 | 只改变“后台检查被拒绝”这一观察项；提示仍安静，重启仍等待凭据操作结束 | 删除检查阶段的拒绝逻辑 |
| 删除重启前的延迟回调 | 切号尚未完成时不再要求等待，破坏凭据写入与重启的顺序 | 保留 |
| 让 Sparkle 默认显示后台更新窗口 | 不再保证后台检查只产生安静提示 | 保留蓝点提示回调 |
| 删除“没有新版本”的特殊处理 | 没有新版本也被显示为失败 | 保留结果分类 |

“后台检查被拒绝”用于观察实现差异，不作为必须保留的产品要求。后台查询版本不修改凭据；手动更新入口的忙碌保护和安装重启前的等待仍存在。

## 实验发现的错误与修复

增加“断网失败 → 下一次后台检查成功且无新版”的固定场景后，基线及六个单项消融版本均保留旧网络错误。组合版修正为无新版时清除旧错误；新网络失败仍明确显示。

最终组合版通过全部 11 项产品行为检查：每小时配置、开关与 UI 通知、安静提醒、可见版本、关闭提醒、凭据操作结束后恰好重启一次、空闲安装不被延迟、无新版不报错、网络失败可见、无新版成功清除旧错误、发现新版清除旧错误。第 12 项仅记录是否阻止后台检查，组合版按设计允许。

`AppUpdater.swift` 从 116 行减至 101 行。删除了 2 个存储状态、2 个 KVO 监听和一个检查阶段的拦截回调。新增 `AppUpdaterTests` 回归用例覆盖旧错误清除。

## 保留的设计与边界

- [Sparkle 官方更新框架](https://sparkle-project.org/documentation/)负责调度、下载、签名校验和安装；不增加另一套定时器、版本比较器、下载器或 shell 自替换流程。
- [每小时检查](https://sparkle-project.org/documentation/customization/)采用框架最短支持间隔 3600 秒，设置页可随时手动检查。
- 蓝点与主页更新行使用同一个版本状态。蓝点用于菜单收起时，更新行位于账号列表和底部工具栏之间，展示版本和更新入口。尚未做真人可用性 A/B 实验，因此不宣称这两个位置已经过用户实验优化。
- 签名、公证以及更新包校验属于安装执行代码所需的验证。本轮未通过故意关闭签名来测试或削弱正式安装链路。
- 对外自动更新需要发布包含 `appcast.xml` 的新版本；当前公开 0.1.6 没有更新源文件。发布仍遵循显式 tag 触发 GitHub Actions 的既有规则。

实验工具限制：Swift 编译器在通过 existential 调用可选 Objective-C throws delegate 时崩溃。测试驱动改用与 Sparkle 相同的 Objective-C 可选回调分发，保留原编译日志；此测试桥接不进入产品代码。

### 发布前真实安装实验

独立临时应用实际完成 0.1.7 → 0.1.8 升级：启动旧版本 → 检测更新 → HTTP 下载带 Ed25519 签名的 ZIP → 解包 → 安装 → 退出旧进程 → 重新启动 0.1.8。读回安装目录的 CFBundleVersion 为 0.1.8，且新进程写出启动标记。测试应用使用独立 bundle ID、自动应答的测试 user driver、本地 HTTP 服务与 ad-hoc 代码签名；不启动正式 Switcher 或触碰账号数据。

原始证据为 `.build/update-install-check/result.json`、events.log、Probe.m 和 run.py。该实验验证真实 Sparkle 安装重启及语义版本比较，正式 GitHub DMG 的 Developer ID、公证和下载完整性另由发布工作流及发布后读回核验。
